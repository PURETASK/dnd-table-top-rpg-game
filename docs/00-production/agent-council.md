# Realm of Nexus / VERDAX — Agent Council v1.0

**Status:** Locked v1.0

The Agent Council breaks the massive Realm of Nexus + VERDAX project into
specialized production lanes. Each agent owns one category of work, with a
defined job, output format, quality checklist, and handoff path.

## Production rule

Each chunk does **one job**: define canon, explain why it matters, show how
VERDAX tracks it, give schemas/data fields, give cause/effect examples, mark
open questions — then **lock it as v1**. Once locked, future chunks reference it
instead of reinventing it.

## Production workflow

1. **Chunk assignment** — each chunk gets one lead agent and one QA agent.
2. **Draft** — lead agent creates the full section.
3. **QA pass** — CANON-WARDEN checks canon, logic, specificity, gameplay usefulness, cause/effect depth, trackability.
4. **Implementation pass** — SCHEMA-FORGE checks tables, fields, prompt inputs, response outputs, UI panels.
5. **Lock v1** — NEXUS-ORCH marks Locked v1.0, lists open questions, allows future expansion.

## Quality gates (every output must pass)

- Does this contradict established canon?
- Does this make the domain feel like a civilization, not a theme?
- Does the faction have a real reason to exist (a real point + a dangerous flaw)?
- Does the NPC act from belief, desire, fear, and secret?
- Does the rumor have source, motive, distortion, and spread?
- Does the consequence chain reach beyond the first result?
- Does the Keeper or Void exploit the situation *logically*?
- Does this create gameplay?
- Can VERDAX track it? Can the database store it? Can the player understand *why* it happened?
